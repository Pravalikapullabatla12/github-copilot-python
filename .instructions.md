# GitHub Copilot Instructions for Flask Sudoku Project

## Project Overview
This is a Flask-based Sudoku solver and game application with a web interface.

## Code Organization & Module Responsibilities

### Sudoku Logic (`starter/sudoku_logic.py`)
- Contains all puzzle solving, validation, and generation algorithms
- **Critical Requirement**: When verifying puzzle uniqueness, always use `count_solutions(..., limit=2)` to check for exactly one solution
- Modifications here affect the core puzzle engine—test thoroughly before committing
- Keep this module free of web/UI dependencies

### Flask Routes & API (`starter/app.py`)
- Defines all HTTP endpoints and server-side logic
- Handles puzzle generation, validation, and game state management
- Integrates with `sudoku_logic.py` for algorithmic work
- Keep routes focused and delegate complex logic to `sudoku_logic.py`

### Browser Behavior (`starter/static/main.js`)
- Manages DOM interactions, event handling, and user experience
- Handles puzzle rendering, cell input, and real-time feedback
- Communicates with Flask backend via AJAX/fetch calls
- Do not modify server logic here—route backend changes through `app.py`

### Styling (`starter/static/styles.css`)
- Contains all visual presentation and responsive design rules
- Keep styling isolated; avoid embedding styles in HTML or JavaScript

## Development Practices

### Testing
- Use **pytest** for all unit and integration tests
- Test files: `test_app.py`, `test_sudoku_logic.py`
- Run tests before and after modifications to catch regressions
- Aim for test coverage of critical paths (puzzle validation, solving, uniqueness checks)

### Change Guidelines
1. **Preserve Existing Functionality**: Do not remove or disable features when adding or modifying code. If refactoring is needed, do so incrementally with tests passing at each step.
2. **Small, Focused Changes**: Make targeted edits to single modules/functions rather than broad rewrites
3. **Explain Decisions**: When implementing non-obvious logic or making architectural choices, include comments explaining the "why"
4. **Test After Every Change**: Ensure pytest suite passes after modifications

## Unique Solution Verification
Sudoku puzzles must have exactly one solution:
```python
# Example pattern to follow
if count_solutions(puzzle_grid, limit=2) != 1:
    # Puzzle is invalid (0 or 2+ solutions)
```
Always validate generated or modified puzzles with this check.

## Code Style Preferences
- Follow PEP 8 for Python code
- Use descriptive variable and function names
- Keep functions single-responsibility
- Prefer clarity over cleverness

## Common Tasks & Where to Implement
| Task | Location |
|------|----------|
| Add new Sudoku algorithm | `starter/sudoku_logic.py` |
| Create new API endpoint | `starter/app.py` |
| Add UI interaction | `starter/static/main.js` |
| Update styling | `starter/static/styles.css` |
| Verify logic changes | `starter/test_sudoku_logic.py` |
| Verify API/UI changes | `starter/test_app.py` |
